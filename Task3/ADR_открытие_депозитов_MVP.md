### **Нефункциональные требования**

| № | Требование |

### **Решение**

[Диаграмма контекста C4](c4-context.svg)

[Диаграмма контейнеров C4](c4-containers.svg)

В АБС появляется модуль депозитов: продукты, версии ставок, согласование специальных условий и обработка онлайн-заявок. Для MVP это остаётся рабочим местом бэк-офиса. Перенос ставок из Excel делается один раз перед запуском; после этого файл не должен жить параллельно как второй источник условий.

Для онлайн-каналов выделяется отдельный сервис заявок с БД MS SQL. Он хранит заявки, статусы, read model ставок и технические записи о доставке. Сервис не является новой учётной системой депозита: окончательные условия и факт открытия по-прежнему определяет АБС.

Такой размер выделения позволяет развивать депозиты без перевода всего монолита на микросервисы. Команда интернет-банка меняет UI и серверную часть обращений к новому API, но обновление SMS в ядре подрядчика не требуется. Сайт обращается к тому же API через свой PHP backend, поэтому правила приёма формы не дублируются в браузере.

**Интеграции**

| Взаимодействие | Как работает |
|---|---|
| Сайт / интернет-банк → API заявок | Синхронный HTTPS REST. Чтение ставок выполняется из MS SQL сервиса. При создании заявки клиентский ключ идемпотентности сохраняется вместе с ней. |
| API заявок → кол-центр | HTTPS-передача лида с сайта. Ответ кол-центра фиксируется; при временной ошибке отправка повторяется обработчиком. |
| API заявок / обработчик → SMS | Банковский SMS-компонент обращается к существующему шлюзу. Код имеет ограниченное время действия. Для уведомлений сохраняется пара «заявка — тип события», чтобы повтор не отправлял SMS заново. |
| Обработчик → адаптер АБС | После коммита заявки в MS SQL обработчик читает outbox и передаёт операции адаптеру. Отметка о доставке появляется только после подтверждения. Ошибка не приводит к потере заявки. |
| Адаптер → АБС | Узкий защищённый интерфейс только для заявок, ставок и статусов. Запросы выполняются пакетно, с ограничением частоты и повторами. В пользовательском запросе этот вызов отсутствует. |
| АБС → контур заявок | Адаптер периодически забирает новые версии ставок и статусы. В MS SQL обновляется read model; каналы видят время последней успешной синхронизации. |

Outbox выбран как временная, но достаточно простая доставка для MVP. Он не требует Kafka и работает в уже имеющемся MS SQL. Когда платформа интернет-банка будет обновлена, тот же адаптер можно перевести на брокер, не меняя канальные API и учётный модуль АБС.

Новые stateless-компоненты развёртываются минимум в двух экземплярах за балансировщиком. MS SQL должен иметь резервирование и процедуру переключения на резервный ЦОД. АБС не включается в схему горизонтального масштабирования: её Oracle и без проекта перегружен, а масштабирование остаётся вертикальным.

Разграничение доступов реализуется в АБС. Сотрудник кредитов может передать параметр риска или решение по согласованию, не получая список депозитных клиентов; сотрудник депозитов не видит кредитные досье. В read model каналов попадают только условия, необходимые для показа.

### **Альтернативы**

| Вариант | Почему не выбран |
|---|---|
| Интернет-банк напрямую вызывает API АБС | Пользовательский трафик ляжет на перегруженную АБС. При её замедлении перестанут работать даже просмотр ставок и форма заявки. Существующий доступ к Oracle повторять нельзя. |
| Вся функциональность добавляется в монолит интернет-банка | Меньше новых компонентов, но заявки, интеграция и SMS окажутся связаны с циклом подрядчика и одной группой серверов. Дальнейший перенос на кредиты будет сложнее. |
| Сразу внедрить Kafka | Для асинхронного обмена подходит, но текущая .NET Framework 4.5 несовместима с выбранным направлением. Отдельная инфраструктура брокера увеличит срок MVP, не устраняя основную ручную операцию бэк-офиса. |
| Оставить ставки в Excel и публиковать файл на сайт | Минимальная доработка, но нет единой версии условий, нормального согласования и контроля доступа. Для персональных ставок этот вариант не подходит. |

### **Недостатки, ограничения, риски**

- Бэк-офис по-прежнему обрабатывает каждую заявку. Рост числа онлайн-заявок может упереться в 50 сотрудников, а не в пропускную способность сервисов.
- Каналы показывают последнюю реплицированную версию ставки. При задержке синхронизации условие могло уже измениться в АБС, поэтому финальная ставка фиксируется только при подтверждении заявки.
- Outbox и периодический опрос создают небольшую задержку статусов. Это приемлемо для MVP, но требует мониторинга очереди и явного статуса «передана в обработку».
- Отказоустойчивость контура заявок не устраняет ограничения АБС. Если АБС недоступна, просмотр последних ставок и сохранение заявок продолжают работать, а подтверждение и открытие депозита ждут восстановления.
- Два ЦОД усложняют эксплуатацию MS SQL и обработчиков. Нужна проверка, что после переключения не работают одновременно два активных обработчика одной и той же задачи.
- В адаптере АБС появляется новый интерфейс, который должна сопровождать команда АБС. Без ограничения частоты и мониторинга он может стать новым источником нагрузки на Oracle.
