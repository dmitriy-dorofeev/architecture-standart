| Код | Требования                         | Комментарий  |
|-----|------------------------------------|--------------|
| F   | Функциональные (Functionality)     | MVP: заявки на депозит на сайте и в интернет-банке. Открытие без бэк-офиса в этот этап не входит. |
| F1  | На сайте новый клиент видит депозиты и актуальные публичные ставки. | Ставки должны приходить из единого источника, а не поддерживаться отдельно на сайте. |
| F2  | На сайте клиент оставляет заявку с Ф. И. О. и номером телефона. | Заявка поступает в работу кол-центру. Менеджер может предложить особые условия; открытие предшествует идентификации в отделении. |
| F3  | В интернет-банке клиент видит депозиты, актуальные и доступные ему персональные ставки. | Персональные условия не должны попасть в публичный каталог сайта. |
| F4  | В интернет-банке клиент выбирает счёт, указывает сумму и подтверждает заявку SMS-кодом. | Повторная отправка формы после сбоя не должна создавать вторую заявку. |
| F5  | Менеджер бэк-офиса видит онлайн-заявку в АБС, проверяет и подтверждает условия. | Ручная операция сохраняется в MVP. После подтверждения клиент получает SMS. |
| F6  | После открытия депозита в АБС клиент получает SMS, а в интернет-банке видит итоговый статус заявки. | Уведомление должно отражать фактическое состояние в АБС, а не только приём онлайн-заявки. |
| F7  | Ставки, правила персональных предложений и согласование специальных условий ведутся в АБС. | Предлагаемая замена ежедневного обмена Excel. Доступ к функциям нужен обоим бэк-офисам, но без раскрытия данных смежного направления. |
| F8  | Для операций со ставками и заявками сохраняется история изменений. | Добавлено для разбора спорных операций и проверки согласования специальных ставок. |
| U   | Удобство использования (Usability) |  |
| U1  | Новые экраны используют действующую дизайн-систему банка. | Ограничение из кейса. |
| U2  | Клиенту показываются понятные статусы: заявка принята, условия подтверждены, депозит открыт, требуется визит в отделение. | Набор статусов зависит от канала. Для сайта не нужен статус онлайн-открытия, если клиент ещё не идентифицирован. |
| U3  | Рядом со ставкой указывается время её последнего обновления. | Добавлено из-за перехода от Excel к репликации: клиент и оператор должны видеть, на какой момент известны условия. |
| U4  | Справочники и каталог ставок открываются без текущей секундной задержки; основные действия не требуют длинных цепочек экранов. | Для чтения ставок использовать локальное представление в контуре канала. |
| R   | Надёжность (Reliability)           |  |
| R1  | Новые компоненты работают 24/7 с целевой доступностью 99,9%. | Требование распространяется на сервис заявок и канальные функции. АБС остаётся ограниченным ресурсом, поэтому её недоступность не должна мешать просмотру последних ставок. |
| R2  | Сервисы развёрнуты минимум в двух экземплярах, запросы балансируются; предусмотрено переключение на резервный ЦОД. | Сейчас интернет-банк использует одну группу серверов в основном ЦОД. Для новых компонентов этот риск нужно устранить. |
| R3  | Приём заявки и постановка её во внутреннюю очередь выполняются атомарно. | Транзакционный outbox в БД сервиса заявок позволяет не терять сообщение между записью в MS SQL и передачей в АБС. |
| R4  | Повторная доставка в АБС и повторный вызов API не создают дубликаты заявок и уведомлений. | Нужны идемпотентные ключи и учёт отправленных сообщений. |
| R5  | Ошибки интеграции с АБС, SMS-шлюзом и кол-центром видны эксплуатации; заявку можно повторно обработать после восстановления. | Ручной повтор не должен требовать прямого изменения записей в базе. |
| R6  | Персональные данные и ключи подтверждения не записываются в открытые журналы. | Добавлено для защиты чувствительных данных при диагностике сбоев. |
| P   | Производительность (Performance)   |  |
| P1  | Чтение справочников и ставок выполняется из локальной БД/кэша без синхронного обращения к АБС. | Сейчас справочные данные при платежах загружаются более секунды. Для новых экранов такая зависимость недопустима; целевой отклик интерфейсных операций — миллисекунды. |
| P2  | Сервис заявок и адаптер интеграции масштабируются горизонтально; состояние не привязано к экземпляру приложения. | Это позволяет распределять нагрузку между серверами и ЦОД. |
| P3  | Обращения адаптера к АБС ограничиваются и выполняются отдельно от пользовательского запроса. | Oracle АБС уже перегружен. Сама АБС масштабируется вертикально, поэтому нельзя переносить на неё пиковый трафик каналов. |
| P4  | Объём реплицируемых ставок ограничен данными, необходимыми каналу. | Не копировать в интернет-банк и на сайт лишние внутренние параметры риска. |
| S   | Поддерживаемость (Supportability)  |  |
| S1  | Для сервиса заявок используются .NET и MS SQL; интеграция с системой кол-центра может использовать Java Spring Boot и PostgreSQL. | Такой набор опирается на уже имеющиеся платформы и специалистов банка. Версии должны быть совместимы с инфраструктурой банка. |
| S2  | Депозитный контур отделён от монолита интернет-банка и допускает дальнейшее расширение на кредитные заявки. | Не требуется переводить весь интернет-банк на микросервисы ради MVP. |
| S3  | API, форматы сообщений, схема данных и правила повторной обработки документируются. | Документация нужна команде АБС, команде интернет-банка и подрядчикам для следующих этапов. |
| S4  | Для заявки используется сквозной идентификатор в журналах канала, сервиса заявок, адаптера и АБС. | Упростит поиск зависших заявок при участии нескольких команд. |
| S5  | Развёртывание, мониторинг и восстановление после отказа описаны в эксплуатационной документации. | Особенно важно при работе двух ЦОД и асинхронной доставке. |
| +R  | + Ограничения (Restrictions)       |  |
| +R1 | Весь внешний и внутренний трафик новых функций передаётся по защищённым каналам; публичные формы доступны только по HTTPS. | Прямое требование для сайта и интернет-банка. Для внутренних вызовов применяется TLS в контуре банка. |
| +R2 | Сотрудники депозитов и кредитов имеют доступ только к данным и операциям своего направления. | Требование ИБ. Разграничение проверяется на сервере, а не только скрытием элементов интерфейса. |
| +R3 | Интернет-банк и сайт не обращаются напрямую к базе или API АБС. | Существующий доступ интернет-банка к Oracle не распространяется на новый процесс. Обмен выполняется через сервис заявок и адаптер. |
| +R4 | Доработка SMS в ядре интернет-банка подрядчиком не допускается. | Отправку кодов и уведомлений выполняет банковский компонент через существующий SMS-шлюз. |
| +R5 | Kafka не используется в MVP как обязательный компонент. | Текущая платформа интернет-банка на .NET Framework 4.5 несовместима с Kafka. Переход рассматривается после модернизации платформы. |
| +R6 | В MVP решения по условиям и открытию депозита принимает сотрудник бэк-офиса в АБС. | Полная автоматизация — отдельный этап на горизонте года. |
| +R7 | Данные сайта с Ф. И. О. и телефоном передаются только авторизованному контуру обработки обращений. | Добавлено из-за чувствительности данных и подключения внешнего партнёра на последующих этапах. |
